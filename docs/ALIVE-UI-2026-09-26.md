# Tutor’s Desk — Alive UI (app-first)

Scope chosen: **app only**, **production-signed APKs only**, **remote crash
reporting off**. The Paper + Ink + Indigo theme and existing teacher workflows
remain. This is an app-first implementation, not a claim that all 50 proposal
items or all native-device audits are complete.

## Implemented

- Shared motion policy combines system accessibility with a persisted Settings
  → Reduce motion switch. Repeating toolkit effects stop on disabled state,
  hidden `TickerMode`, reduced motion and app background; they respond to runtime
  enable/period changes. No global animated aurora was introduced. Decorative
  offline/error blinking was removed; decorative pulse/shine/halo/legacy aurora motion is opt-in (busy indicators explicitly opt in).
- Entrance stagger is capped at 240 ms with 420 ms entrances (about 660 ms total),
  skips spacer widgets and becomes immediate under reduced motion. Shared busy
  indicators become static hourglasses. Shared tactile controls support keyboard
  activation as well as touch. Existing directional page transitions remain;
  reduced motion removes their spatial transition.
- Home gets a signature Create card, semantic teal OMR/purple AI actions, a local
  draft continuation affordance read from the stored snapshot, and saved-paper
  metadata. It does not invent completion percentages, verified states or counts.
- Tab changes use a short directional crossfade while preserving visited AI/tool
  state, including unsent attachments. Hidden tabs cannot tick, take focus, accept
  input or contribute semantics. The library refreshes on each visit.
- Branded, responsive sign-in with the real logo, feature labels and bounded
  entrance. Existing password sign-in, reset and sign-up navigation are retained.
- First-frame startup screen runs real initialization steps in dependency order,
  shows completion only after each returns, and retries failed steps without
  rerunning completed ones. Question-bank loading precedes cached overlays;
  paper backup restoration finishes before home reads the library. Network
  refresh remains background work. Existing account/profile gates remain.
- Shared paper/AI/OMR step and activity feedback is animated and accessible, but
  remains driven by actual controller/server events. Empty/invalid step indices
  are safe. Question-card changes have a brief entrance; preview says PDF ready
  only after rendering returns. Local draft save status no longer uses a cloud
  icon. Printing/sharing is not presented as proof of a saved file or print job.
- OMR camera pause/resume fixes: restart after the controller is cleared, serialize
  initialization/disposal, invalidate stale async work, stop watchdogs/background
  frames, reset confidence and ignore stale capture results. Existing real frame
  analysis and manual/system-camera fallback remain; no fake detections.
- Bounded local diagnostics store error type, app-code locations, build, platform
  and time, not exception messages, account identifiers, payloads, attachments or
  arbitrary URLs/paths. Settings can inspect/clear records. Native crash logging
  is redacted; corrected and legacy log locations are consumed without displaying
  raw crash contents. No crash SDK or remote transport is installed.
- Strict production signing, certificate pin and pre-distribution verification;
  no fallback artifacts. See [RELEASE-SIGNING.md](RELEASE-SIGNING.md).
- Fixed an uninstall data-loss gap the signed-only decision makes material:
  `autoSave()` only wrote the app-scoped backup Android deletes on uninstall,
  while the library screen claimed a Download-folder copy "survives
  uninstalling the app", and the native handler hardcoded its MediaStore
  destination folder while reporting a different one to Dart. Automatic saves now write
  `Download/TutorsDesk/tutors_desk_backup.json` via MediaStore (no permission on
  Android 10+), a manual backup action was added to My Papers, failure is
  reported honestly, and the misleading message is gone. Restore on a fresh
  install reads that shared copy, including OMR answer keys.
- Three further real defects found while testing that fix:
  1. `restore()` added papers to the list returned by `loadEntries()`, which is
     **unmodifiable when no index exists** — i.e. precisely on a fresh install.
     Automatic restore after a reinstall therefore always failed silently. It
     now copies into a mutable list first.
  2. Concurrent shared copies raced over one fixed temporary source file; they
     are now serialized with unique temporary names.
  3. An automatic save of an **empty** library could overwrite a good backup —
     exactly the window between a wipe and the restore. Empty snapshots now
     never replace an existing backup, and the My Papers backup action says
     "nothing to back up yet" instead of writing an empty file.

  The restore defect was found from the local diagnostics this pass added: the
  recorded entry carried the error type and app-code frames only, which was
  enough to identify the failing line without exposing content.

## Preserved contracts

All four AI Tools modes retain photo/PDF attachments and one-tap Run submission.
Selecting files stays local until Run. Bengali prose remains required except
English subjects; digits remain English. The independent checker, language repair
budget, authenticated gateway, quotas and file/privacy bounds are unchanged.
No separate MiMi chat, unsupported CQ promise, audio mode or attachment checkbox
has been added. Existing key/model overrides are untouched.

Admin upgrades are deferred. No Supabase, SQL or Netlify deployment is required
for these app changes. The existing `deployments/content-studio/content-studio-update.zip`
and v5 gateway bundle remain unchanged and available in GitHub.

## Deliberately deferred (app-first scope)

Not implemented in this pass, and not claimed as done:

- Admin/web studio motion and usability (sidebar animation, animated counters,
  skeleton loading, drop-zone feedback, status badge transitions, save/publish
  micro-interactions, mobile drawer, `Ctrl+K` command center, keyboard
  shortcuts, scoped `[data-task-button]` disabling, session-expiry handling,
  upload progress/cancellation, object-URL and worker cleanup).
- A redesigned multi-step create-paper stepper with per-step slide transitions;
  the existing stepper and its animated progress bar remain.
- An animated OMR "scanning line" or staged detection checklist. Capture
  guidance still reflects only real frame analysis.
- Remote crash reporting (Sentry/Crashlytics) — deferred by decision.
- A full accessibility audit of older dialogs and specialty screens.
- Animated recent-paper cards beyond the shared entrance stagger.

## Verification and remaining checks

Added Flutter regressions cover preference persistence, reduced motion, loop
lifecycle, tab state, keyboard activation, boot dependency/retry behavior,
truthful activity labels, narrow sign-in layout, diagnostic privacy/bounds and
signing policy. Existing AI/language/server regressions must continue to pass.
Local server suite: **77/77 passed**. Dart WASM formatting is a syntax/format
check, not a Flutter type-check; CI supplies Flutter analyze/tests and Android
configuration validation plus native-source compilation without APK packaging. Record the exact CI result in the PR after it finishes.

Before production delivery, a trusted maintainer must configure the existing
release signing identity and certificate pin; the production build and APK
certificate verification must then pass. This session cannot read repository
secret/variable settings (GitHub returns permission denied for those endpoints).

Still requires real Android smoke testing: cold/warm startup, offline/cache
fallback, saved-draft/library restoration, keyboard/large-font navigation,
normal and reduced motion, switch tabs with unsent attachments, PDF rendering /
sharing / print cancellation, backup copy and restore across a real uninstall/reinstall, camera permission
prompt, background/resume during
initialization and capture, system camera fallback, actual OMR sheets and
low-end-device frame/memory/battery behavior. Automated widget checks are not
proof of camera hardware behavior or production performance. Older dialogs and
specialty screens have not received a complete accessibility audit.

Do not uninstall an existing debug-signed installation simply to install a new
production identity; local data migration needs a safe plan first. No merge or
production deployment is authorized by this update.

## Colour language (added after the first test build)

A review of the first test build reported that the palette "disappeared". The
tokens were never missing — they were unused. Measured before the change:
`AppStyle.gradient` had **zero** consumers, `AppColors.writing` and
`AppColors.science` were referenced nowhere, `AuroraRibbons` was referenced only
by its own file, and the backdrop washed at 5%/3.5% alpha.

Now colour carries navigation meaning, and cards stay paper white — the accent
appears only in the icon well, a border, the progress indicator and selection:

| Area | Token | Hue |
| --- | --- | --- |
| Desk / create | `AppColors.primary` via the preset accent | indigo |
| My Papers | `AppColors.science` | sky |
| OMR | `AppColors.omr` | teal |
| AI Tools | `AppColors.ai` | purple |
| English / writing | `AppColors.writing` | pink |
| Still aligning a sheet | `AppColors.warning` | amber |

- `AppStyle.mood` + `moodColor` drive one backdrop tint. Switching tabs animates
  the tint over 300 ms instead of jumping, and leaving the paper editor restores
  the accent for the tab the teacher returns to.
- The backdrop now paints `AppStyle.gradient`, so the workspace preset is
  visible rather than only affecting a nearly invisible wash.
- `AuroraRibbons` became a translucent veil (no opaque base, three ribbons
  sampled at 8 px instead of five at 4 px) and is used in exactly four places:
  sign-in, sign-up, the home hero and nowhere else. The paper editor, the OMR
  scanner and question reading screens stay still.
- OMR stops using red as an aiming guide: teal means the sheet is readable,
  amber means keep aligning, and red is reserved for a genuine fault.

`test/workspace_color_test.dart` locks the mapping, proves the gradient reaches
the screen, and asserts the aurora schedules no frames when disabled or when
motion is reduced.
